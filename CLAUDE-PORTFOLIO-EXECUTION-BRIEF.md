# Claude Portfolio Execution Brief

## Role

Act as a senior portfolio editor, evidence architect and repository maintainer working for Christopher Swarup.

Your job is to turn the approved professional evidence into a polished private GitHub portfolio suitable for potential employers, investors and advisers.

The repository must feel like a senior operator's due-diligence room: commercially sharp, easy to navigate, evidence-led, honest about limitations and free from personal or confidential material.

Do not start with Lynr or ThinkBud. Build the operator foundation and skills evidence first.

## Primary objective

Make the portfolio answer two questions quickly and credibly:

### For potential employers

Can Christopher diagnose complex GTM problems, design the operating system underneath growth, lead cross-functional transformation and make the change usable?

### For potential investors and advisers

Does Christopher possess repeatable operator insight that can be converted into differentiated services, tools, workflows or products?

## Non-negotiable boundaries

Never add, copy, infer or preserve:

- Personal phone numbers, home addresses or private email addresses
- Family or child information
- Passports, identity records or Companies House identity-verification material
- Payslips, tax records, medical records, employment contracts or legal correspondence
- Passwords, tokens, API keys, environment files, recovery codes or backup codes
- Customer, prospect, employee or partner lists
- Production CRM, marketing, financial, product or usage data
- Internal screenshots, dashboards, system exports or private URLs
- Employer-owned source documents, slide decks, spreadsheets, prompts, code or exact configuration
- Confidential employer names or internal project names inside reconstructed case studies
- Claims or metrics that cannot be verified and safely generalised
- Third-party training material presented as Christopher's original intellectual property

A private repository does not remove these restrictions.

## Source-treatment rule

> Rebuild the insight from a blank page. Never migrate, lightly redact or cosmetically rewrite the source artefact.

Historic employer material may only be used as professional memory to identify themes, decisions, trade-offs and lessons. All portfolio content must be independently structured and written.

Use synthetic organisations, fictional people, generated records and generic field names for examples.

## Required format for every skill

Each skill README must include:

1. Executive summary
2. Business problem addressed
3. Appropriate use cases
4. Preconditions and required evidence
5. Input contract
6. Analysis or decision rules
7. Output contract
8. Human review and approval point
9. Exception and override handling
10. Failure modes
11. Limitations
12. Synthetic worked example
13. Evidence label
14. Source-provenance declaration
15. Confidentiality declaration

Do not publish original internal prompts. Reconstruct a clean, company-neutral specification that proves the design thinking without revealing proprietary implementation.

## Workstream 2 — Improve employer and investor presentation

The landing experience must look deliberate and senior.

Improve navigation so a reviewer can reach the most relevant evidence in two clicks or fewer.

Required review paths:

- Recruiter or talent leader
- CMO or Marketing leader
- CRO, COO or Revenue leader
- Founder, investor or adviser
- Technical or operations reviewer

Use clear headings, concise summaries and explicit evidence labels. Avoid decorative badges, inflated language, fake logos, unsupported maturity claims and visual clutter.

The portfolio should show:

- Range without looking unfocused
- Depth without exposing confidential detail
- Commercial judgement rather than tool administration
- Transformation leadership rather than only frameworks
- AI capability grounded in process, data and accountability
- Founder potential without allowing venture concepts to overshadow the operator evidence

## Git workflow

- Inspect before editing.
- Work on a dedicated branch where the environment supports it.
- Prefer a pull request with a clear summary and file-by-file rationale.
- Do not rewrite or delete existing control documents without explicit justification.
- Keep commits focused and descriptive.
- Run a confidentiality and personal-data review before requesting approval.
- Never commit a file merely because it exists in Drive, Notion or a local folder.

## Definition of done for the skills phase

The skills phase is complete when:

- Every evidenced original skill or agent has been inventoried
- Every included skill has a useful portfolio-safe specification
- No proprietary prompt or internal implementation has been copied
- The relationship between the command centre and specialist skills is clear
- At least three skills have synthetic worked examples
- At least one skill has a runnable demonstration
- Employer and investor reviewer paths link to the catalogue
- All files pass provenance, personal-data, confidentiality and security review

## Quality bar

The final portfolio should feel credible to a CMO, CRO, COO, operating partner or early-stage investor.

It should demonstrate senior judgement, implementation realism, intellectual honesty and repeatable operating capability. It must never look like a generic AI-generated knowledge base, a dump of old company work or an over-designed personal website translated into Markdown.
