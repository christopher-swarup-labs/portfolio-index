## Known production gaps

These gaps must be resolved case by case:

1. **Contribution attribution** — some source artefacts were collaborative; each case must isolate Christopher’s role accurately.
2. **Metric verification** — exact claims in CVs, interview documents or retrospectives need independent support or generalisation.
3. **Outcome evidence** — not every strong framework has a safely disclosable result metric.
4. **Visual reconstruction** — diagrams must be redrawn in a neutral portfolio design.
5. **Implementation detail** — enough detail must be shown to prove substance without exposing proprietary configuration.
6. **Adoption evidence** — training, behaviour change and governance need to be shown alongside system design.
7. **Chronology** — composite cases must not imply that all elements were delivered in one role or programme.
8. **External facts** — market claims in venture documents require fresh research before publication.

## Completeness rule for future discoveries

When additional Drive material is found, it should be processed through this test:

1. Does it reveal a genuinely new capability?
2. Does it strengthen an existing case with better implementation or outcome evidence?
3. Is it original operator work, supporting evidence, an independent exercise or third-party reference?
4. Can the insight be reconstructed safely?
5. Does it change the current build order?

A new file does not automatically create a new case study. It must add a distinct decision, capability or proof point.
