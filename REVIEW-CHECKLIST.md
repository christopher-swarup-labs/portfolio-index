# Portfolio Review Checklist

Use this checklist before committing any new portfolio artefact.

## Ownership and purpose

- [ ] The business purpose of the artefact is clear.
- [ ] Christopher owns the new work or has permission to use the source.
- [ ] The artefact was created specifically for the portfolio.
- [ ] The source treatment is recorded in `SOURCE-PROVENANCE.md`.

## Employer and customer confidentiality

- [ ] No employer name appears in an anonymised case study.
- [ ] No customer, employee, partner or supplier name appears.
- [ ] Internal programme names and terminology have been removed.
- [ ] Exact dates, volumes, headcounts and technology combinations have been generalised where identifying.
- [ ] No original slide, spreadsheet, screenshot or document has been uploaded.

## Personal information

- [ ] No personal email addresses, phone numbers or home addresses are present.
- [ ] No employee, customer, child or family information is present.
- [ ] No identity, payroll, banking, tax or health information is present.

## Data and examples

- [ ] All example records are synthetic.
- [ ] Synthetic names and domains are clearly fictional.
- [ ] No real CRM IDs, account IDs, campaign IDs or timestamps remain.
- [ ] Metrics are supportable and do not identify a former employer.
- [ ] No outcome has been invented or overstated.

## Security

- [ ] No credentials, tokens, API keys, passwords or connection strings are present.
- [ ] No private links contain embedded access parameters.
- [ ] Secret scanning has passed.
- [ ] File names have been checked for sensitive terms.
- [ ] Git history has been checked if a sensitive file was ever added.

## Documents and metadata

- [ ] Hidden tabs, comments, speaker notes and tracked changes have been removed.
- [ ] File properties and author metadata have been reviewed.
- [ ] Embedded images and links have been checked.
- [ ] Archived or compressed files are not included.

## Quality

- [ ] The commercial problem is clear.
- [ ] Christopher's role and decisions are clear.
- [ ] Constraints and trade-offs are visible.
- [ ] The implementation sequence is practical.
- [ ] Governance and adoption are addressed.
- [ ] Measures are defined.
- [ ] Limitations and uncertainty are stated.

## Repository boundary

- [ ] Nothing has been copied from the ThinkBud repository.
- [ ] Nothing has been copied from another code repository without explicit approval.
- [ ] The artefact belongs in this repository.
- [ ] Cross-repository links reveal no restricted information.
